# Автовосстановление соединения (Android)

Настройки → Сервис → Автовосстановление соединения. По умолчанию включено.
После изменения настройки применяется обычная перезагрузка сервиса.

- Сервис пассивно получает дельты байтов из того же источника, что меню
  «Соединения», с интервалом 5 секунд по локальному IPC. Сетевая проба для
  получения этих счётчиков не создаётся; открывать меню не требуется.
- Новые входящие данные пользовательского соединения подтверждают работу на
  10 секунд. Одни исходящие/буферизуемые попытки не доказывают получение ответа.
  Незакрытая запись без прогресса не блокирует HTTPS-проверку и поиск замены.
- Начальные накопленные счётчики являются базой сравнения, не текущей активностью.
  Также учитывается свежий прирост при закрытии короткого соединения между тиками.
- DNS-записи и служебные inbound проверки/поиска исключены из подсчёта.
  Свежие входящие данные во время проверки делают её результат непригодным для
  автоматического переключения. При неизвестном состоянии IPC сначала
  восстанавливается подписка, а отсутствие трафика не предполагается.
- Хранятся только ID и счётчики незакрытых соединений, без истории или списка
  посещённых адресов. Секундного опроса и отдельного частого таймера нет.
- Проверка HTTPS идёт через отдельный loopback HTTP CONNECT inbound и основной
  outbound/endpoint активного профиля, не через прямое Android-соединение.
- Проверяются два независимых адреса, ожидается HTTP 204 и корректный TLS.
  Один успешный ответ означает доступность туннеля. Это проверка обрыва,
  а не гарантия скорости или доступности каждого сайта.
- Обычный фоновый такт — 5 секунд; после неудачи — 2 секунды.
  Нет wake lock или будильников, принудительно пробуждающих устройство.
- При здоровом соединении интервал 5 секунд (запросы только без свежих входящих данных). Для поиска нужны два провала
  обоих адресов; между неудачными раундами выдерживается 2 секунды.
- Без физической INTERNET/NOT_VPN сети с Android VALIDATED (Android 6+),
  при captive portal и в Doze поиск приостановлен. После смены сети — пауза
  15 секунд. Приложение не включает Wi-Fi, мобильные данные и не снимает авиарежим.
- Ручная остановка VPN, отзыв разрешения, выбор другого профиля и групповая
  проверка отменяют/блокируют автоматический выбор. Поздний результат поиска
  не должен перезаписывать ручной выбор.
- За раунд подготавливаются до 9 совместимых с текущим режимом сервиса
  профилей, проверяются группами по 3, с лимитом поиска 60 секунд.
  Следующий неудачный раунд продолжает список; интервал растёт от 1 до 5 минут.
- Для проверки используется временный расширенный runtime с прежним TUN и
  маршрутами активного профиля. Скачанные файлы конфигов не изменяются.
- Замена повторно проверяется в настоящем runtime перед сохранением выбора.
  После успеха обновляются имя в уведомлении и выбранный профиль на экране.
  При неудаче восстанавливается исходный runtime, если сервис не остановлен.
- Перезагрузка runtime и переключение прерывают существующие соединения.
- Профили с другим режимом сервиса не выбираются автоматически.
- Диагностика: adb logcat -s ConnectionRecovery BoxService singbox

Для этой правки не запускались Gradle, сборка APK/ядра и тесты.
На устройстве необходимо проверить обрыв сервера, выключение обеих сетей,
смену Wi-Fi на мобильную сеть, ручной Stop и ручной выбор во время поиска.


Время реакции на остановку обмена — ориентировочно 30 секунд: локальные дельты
5 с, свежесть входящих данных 10 с, два раунда по двум HTTPS-адресам с лимитом
2 с на адрес и паузой 2 с. Поиск кандидатов добавляется к этому времени;
неизвестная сеть, sleep и ручное отключение сохраняют приоритет над таймером.
